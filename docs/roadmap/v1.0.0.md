# v1.0.0 — the north star

Not a timeline. A shape.

## What makes a 1.0 1.0

v0.x is "the shape is right, details are moving." v1.0 means:

- **The public API won't break on a dot-release.** `AIBackend`, `AppContainer`, `BuzzPattern` etc. are stable for contributors.
- **The shipped feature set is complete enough** to be useful on its own.
- **The tests cover the crypto / parser code** we tell users to trust.
- **The release pipeline is signed and verifiable.**

## Must-have for 1.0

- Real passthrough AR Home with hand-tracking.
- Signed releases + published signing fingerprint.
- Unit tests for `PayloadVerifier` + `SelfUpdater.compareSemver`.
- A reliable, documented path for users to migrate between keystores if we ever lose and regenerate one.
- Build Tools SDK stable; third-party widgets would at least need no breaking changes.
- Documentation site (mkdocs-material on GitHub Pages).
- A `v1.0.0` release note that's readable and complete.

## Nice-to-have for 1.0

- F-Droid listing.
- An iOS/macOS companion that reads some of the on-device data (not realistic without a bridge; parking).
- Unity-based AR Home as an alternative renderer (keeping the current Compose preview as the fallback).
- Accessibility audit passed.
- Localization scaffolding (en-only for 1.0, but the strings in strings.xml instead of hardcoded).

## Won't be in 1.0

- Any Meta-signed capability (we can't; see [reverse-engineering/avb-chain.md](../reverse-engineering/avb-chain.md)).
- A cross-platform mobile companion.
- Multi-user on-device profile switching (that's a Meta OS capability, not ours).

## How we get there

Through v0.2, v0.3, … milestones. Each one picks a cluster of roadmap issues and ships them together. No forced march; when 1.0 feels right, it'll feel right.
